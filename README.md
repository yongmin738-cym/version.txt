새 버전 알림·내려받기 추가 (updater.py 신설)

GitHub 의 version.txt 에 최신 버전을 적어 두면 프로그램이 읽어서 새 버전이 있을 때 알려 주고, 눌러서 바로 내려받아 교체한다. 서버 불필요.

version.txt
    VERSION=5.6
    NOTES=측구 U형 자동 인식        <- 여러 줄 가능
    URL=https://github.com/<계정>/<리포>/releases/latest/download/RoadToolkit.exe
    MIN=5.5                        <- (선택) 이보다 낮으면 강제 업데이트
URL 을 releases/latest/download 로 두면 새 릴리스를 올릴 때마다 자동으로 최신을 가리킨다. 주소를 고칠 필요가 없다
버전 비교는 숫자 튜플로 한다 (5.9 < 5.10 이 올바르게 나온다)
실행 중인 exe 는 스스로를 못 덮어쓰므로, _업데이트.bat 을 만들어 프로그램이 끝난 뒤 파일을 바꾸고 다시 띄운다. 교체가 막히면 _새버전_RoadToolkit.exe 로 저장하고 폴더를 열어 준다
version.txt 가 없거나 인터넷이 안 되면 조용히 넘어간다(알림 없이 실행)
APP_VERSION 하나만 올리면 창 제목의 버전 표시도 같이 바뀐다
build_exe.bat 에 --hidden-import updater 추가

zip 배포로 변경 (브라우저·백신 차단 때문)

exe 를 그대로 올리면 브라우저가 "일반적으로 다운로드되지 않는 파일" 로 막고 백신이 격리하는 일이 많다. 서명이 없어서 생기는 일이고 확정 탐지가 아니다.

릴리스에 RoadToolkit.zip 을 올린다 (exe 직접 올리지 않음)
version.txt 의 URL 도 .zip 으로
업데이트가 zip 을 받으면 extract_exe() 로 안의 exe 를 꺼내 교체한다. exe 가 루트에 있든 폴더 안에 있든 찾아내고, 여러 개면 큰 것을 고른다 (세 가지 배치로 시험 완료)
.exe 주소를 그대로 둬도 동작한다 (prepare_new_exe 가 확장자로 판단)

근본 해결은 코드 서명 인증서(연 20~50만원, 사업자 확인 필요)다. 배포 규모가 커지면 검토할 것. 사내 소수면 zip + 안내문으로 충분하다.

릴리스 설명문: 릴리스_설명문.md 로 따로 만들어 두었다. 다운로드 차단·SmartScreen·백신 격리 대처법이 들어 있어 문의가 줄어든다.
